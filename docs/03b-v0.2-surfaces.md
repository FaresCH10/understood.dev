# 03b — v0.2 Surfaces: User Flows & Wireframes

**Document 3b of 8** · Version 0.1 · Date 2026-11-12
**Owner:** Founder · **Status:** Design complete — build only after v0.1 pilot · **Related:** [PRD](./02-prd.md) · [v0.1 Flows & Wireframes](./03-user-flows-wireframes.md)

---

## Why this document exists

The v0.1 doc listed ten surfaces as explicitly deferred. This document designs them now — so the pilot build leaves the right seams — without pulling any of them into v0.1.

Two rules apply throughout:

1. **No v0.2 surface may weaken a v0.1 principle.** One link and zero install (P1), speak-don't-type (P2), proof over receipts (P3), preview before share (P4), never strand a worker (P5), the board is the product (P6), boring beats clever in workers' hands (P7).
2. **Every surface has a v0.1-compatible fallback.** WhatsApp fails → group link. Push denied → personal inbox. Video unsupported → audio + text. Kiosk offline → cached flow. Billing unconfigured → manual invoice. The product never depends on a v0.2 surface existing.

Build order stays: ship v0.1, run the pilot, then turn these on in the rings defined in §1.

## 1. The v0.2 map and release rings

| Ring | Surfaces | Why this order |
|---|---|---|
| **v0.2.0 — Scale the pilot** | Team seats & permissions · WhatsApp API receipts/templates · Personal inbox & push · Scheduled sends · Billing | These are what make the second and third customers possible without the founder doing manual work for every org |
| **v0.2.1 — Prove value** | Analytics · PDF compliance pack · Translation glossary | These are what make renewals and upsells obvious — evidence, insight, and quality |
| **v0.2.2 — On-site & rich media** | Kiosk mode & badge QR · Video instructions | Highest operational cost; only worth it once crews and sites are asking |

Dependency sketch:

```
personal worker token ──► personal inbox ──► push
        │                     │
        ├──► WhatsApp per-worker delivery ──► receipts on board
        │
        └──► kiosk badge QR

seats & roles ──► billing accountability ──► audit "who sent what"
billing ──► plan entitlements (analytics, PDF, kiosk, video)
glossary ──► pipeline quality (independent)
```

Shared foundations to reserve in v0.1 code now: per-worker tokens, an actor field on every action, org-level feature flags, notification preferences, and a plan/entitlement check that v0.1 simply always resolves to "pilot: all on".

## 2. Surface 1 — WhatsApp Business API receipts and templates

### Purpose

Replace manual link-pasting with per-worker delivery through WhatsApp, and surface delivered/read receipts on the board. The group link stays as the fallback and the everyday alternative — WhatsApp becomes a channel, not the product.

## 3. Surface 2 — Worker personal inbox and push opt-in

### Purpose

Give every worker a permanent personal link that opens their own inbox: current instructions, done history, language preference. Add web push so a new instruction reaches them without the supervisor re-pasting links. Still no app store, still no password.

### Flow

```
Supervisor shares (WhatsApp message or badge QR)
   └─ worker opens personal link (token identifies them)
        ├─ inbox (new → done)
        │    ├─ tap instruction → v0.1 worker flow
        │    └─ after first completion → "Get notified" card → enable push
        └─ "Not me?" → sign-out screen (shared-phone safety)

### Purpose

Charge customers without handling card data, in a way that works from Lebanon. All payment flow runs through a merchant of record (Paddle or Lemon Squeezy — verify Lebanon seller support). Our screens explain the plan, count active workers, and hand off.

### States

| State | Behavior |
|---|---|
| Pilot / invoiced | Billing tab shows a friendly note + "Activate subscription"; no locks |
| Limit warnings | At 80% / 100% of plan worker cap: in-app banner with options (upgrade or archive workers) — nothing is ever blocked mid-instruction |
| Past due | Banner + grace 14 days; product stays fully usable; MoR retries payment |
| Canceled | Read-only + export for 30 days, then deletion per policy; wording is kind, not hostile |
| Upgrade | Immediate, prorated |
| Downgrade | End of period, only if active workers fit the new cap |

### Decisions

- **D28 —** No card fields in our app, ever. PCI scope stays at zero.
- **D29 —** Monthly billing at launch; annual plans wait for cash-flow needs.
- **D30 —** Seats are unlimited on all paid plans; billing only counts active workers.
- **D31 —** Feature gating is by ring (Starter: core; Growth: analytics, compliance PDF, kiosk, video; Scale: SSO and residency later).

Serve crews who don't carry phones: a shared site tablet at the entrance, locked into Understood, where a worker scans a printed badge QR or taps their name, completes the instruction, and the tablet resets for the next person.

### Flow

```
Supervisor: Crew page → [ Set up kiosk ] → pick crew → set 4-digit exit PIN

Exit: long-press corner (3s) → PIN → kiosk off
Inactivity 90s at welcome → stays; during a session → prompt "Still there?" then reset

## 7. Surface 6 — Scheduled sends

### Purpose

Fix the daily rhythm: briefings at 07:00, reminders at 14:00, standing policies monthly. The supervisor composes and reviews now; distribution happens on time — without the supervisor remembering to press anything.

### Flow

```
Composer → Preview & share
   ├─ [ Send now ]        (v0.1)
   └─ [ Schedule ] → date & time (org timezone) → optional repeat (weekly/monthly) → confirm
                        └─ status: scheduled; variants generated now; link inactive until send time

Scheduled queue (Home → Scheduled tab)
   ├─ edit schedule / cancel (returns instruction to draft)
   └─ at send time → status: shared → deliveries + notifications begin
```

### S-30 · Worker — not yet available

```

```

### Rules

- Variants are generated and reviewed at schedule time; no AI runs at 07:00 (predictable cost, zero morning failure risk).
- The link token exists but is inactive until send time; early openers see W-19's "not yet available" state.
- Recurring sends create a **delivery round per occurrence** — one board per round, grouped under one series; cached audio is reused, so the monthly policy costs almost nothing.
- Cancel returns the instruction to draft with everything intact; confirm modal explains this.
- If automated WhatsApp distribution fails at send time, links fall back to the group message and the supervisor gets an alert.

### Decisions

- **D35 —** Generate at schedule creation, distribute at send time.
- **D36 —** Each recurring occurrence is its own delivery round; evidence never mixes dates.
- **D37 —** All times displayed in org timezone with the GMT offset shown at the point of choice — never a hidden timezone.

- Long ranges cap at 500 deliveries per pack; beyond that, CSV is the recommended tool.
- Growth plan and above (D31).

### Decisions

- **D38 —** Verification proves integrity, not content; worker details stay in the PDF the customer controls.
- **D39 —** One record ID per pack, hashed over the exact dataset included.

## 11. Surface 10 — Video instructions

### Purpose

Some instructions are physical: how to strap a load, how to tag a scaffold. A 45-second video with subtitles in the worker's language beats any paragraph. v1 scope: short recorded clips, translated subtitles, audio-only fallback — no AI dubbing yet.
